## 再次实车失败与规划器对照

11:18:45 第三点返程开始，随后至 11:19:51 共出现 8 次 `GridBased: failed to create plan, no valid path found`。这段时间控制器没有收到新的路径跟踪目标；行为服务器执行的是等待和后退恢复。因此本轮不动的直接原因是返程规划失败。前进限速提高不能解决没有路径的问题。

本轮实车仍同时加载了三个规划器：允许倒车的 `GridBased`、仅前进的 `RecordedDetour`，以及 `RecordedEntry`。Qt 勾选巡航联锁时曾自动传入 `enable_recorded_routes:=true`，现已改为显式 `false`，保留巡航执行器与 guard。

三规划器结果目录为 `/tmp/patrol_return_probe_nnixfcc0`，单规划器结果目录为 `/tmp/patrol_return_probe_8wslhfm7`。两组测试都没有启动底盘或传感器，也未加入实车实时障碍层；这些是单次测量，三规划器在静态测试中仍能成功，尚未完整复现实车规划失败。

这组差异使两个 SmacHybrid 实例之间的影响成为优先怀疑项。[Humble 源码](https://github.com/ros-navigation/navigation2/blob/humble/nav2_smac_planner/src/node_hybrid.cpp)的 `NodeHybrid` 使用共享运动表及距离启发式表，两个实例分别采用 REEDS_SHEPP 与 DUBIN；不同运动模型的共享数据可能影响返程搜索。这是结合源码和对照结果作出的推断，实车实时成本地图、定位偏差和负载仍可能参与失败，不能据此认定唯一根因。

## 前进上限提高至 0.8m/s

按用户要求，三套普通导航配置同步提高 `FollowPath.desired_linear_vel` 和 `velocity_smoother.max_velocity[0]` 至 0.8，`hardware.yaml` 的 `chassis.max_speed` 同步为 0.8，避免底盘桥继续限制到 0.6。倒车仍为 0.3m/s，加速度 0.4m/s²、减速度上限 0.6m/s²，以及弯道、障碍和终点减速设置保持原值。直线开阔段可使用新的前进上限，实际速度仍以里程计反馈为准。

构建完成后核对安装目录，三套普通导航配置的控制器、平滑器和底盘桥前进上限均为 0.8，倒车均为 0.3，默认规划器列表均仅有 `GridBased`。35 项离线配置/底盘逻辑检查通过；7 项真实 Nav2 与 JD03 桥的隔离仿真测试全部通过，用时 111.83 秒，覆盖直线、倒车、折返点换向、目标改变、障碍重规划、实际 Reeds-Shepp 停车路径及多点导航。

提速后的直线测试包含 12cm 初始横向偏差、8° 朝向偏差及 5mm 定位扰动，最高控制指令为 0.8m/s；模拟底盘反馈最高约 0.806m/s（CAN 速度量化），稳定段横向偏差最高约 6.9cm，最终位置误差约 2.0cm。以上为隔离仿真结果，实车返程与制动距离仍待现场验证。

Qt 启动参数更新需要关闭并重新打开本地客户端；之后重新启动导航流程，控制器、平滑器和底盘桥才会加载新速度与单规划器配置。
