# 2026-10-26 建图保存流程交付记录

## 问题和最终行为

旧 UI 把“数据是否保存”与“是否至少得到六条合格回环”绑定，短路线、单程或
重叠不足会直接报保存失败，需要人工离线恢复。新 UI 保存独立地图包，
回环是否通过是单独状态，不再作为保存数据的前提。

保存正常的单程数据会生成 PCD、检查报告和配套 PGM/YAML。回环通过时采用修正位姿，
优化被拒绝时保留前端位姿和拒绝原因，不输出变形后的优化地图。传感器或时间戳异常
尽可能归档已有数据并给出操作说明，禁止直接载入导航；无数据或真实写入错误仍明确报错。

每次保存使用独立目录，现有导航图不变。UI 提供“打开保存目录”和“载入本次地图”，
后者会选择配套 PCD/YAML 并切换显示方案，要求先停止建图，不会自动启动导航或发送行驶目标。
新图被选择后需重新设定实车位姿、核对点云和旧路线坐标。

回环候选的历史时间过滤从 300 秒调整为 60 秒，同时保留索引间隔 30 和全部配准质量检查。
该时间是匹配过滤参数，不是保存最短时间。保存没有“必须五分钟”或“必须回起点”的条件。

## 接口与部署

- UI 使用新增 `/loop_closure/save_bundle`，`std_srvs/Trigger` 返回含实际文件路径与状态的 JSON。
- `success=true` 表示 PCD/报告落盘，不表示地图已通过回环或实车导航验收；二维切片完成由 UI 单独确认。
- UI 核对返回目录、PCD SHA256 和报告状态后，才投影这份 PCD，避免混用旧切片。
- 新快照位于 `map_session_*/exports/<时间>/map.*`，保存失败不会移走现有导航地图。
- 旧 `/loop_closure/save_map` 和 `/map_save` 仍保留严格检查行为，供旧 CLI 和验收脚本兼容，不是新 UI 的保存入口。
- 新 UI 保存不更新网页“当前导航图”，避免尚未采用的新图与当前导航坐标混用。
- 两个 Python ROS 包和桌面 UI 已构建。正在运行的旧 UI 不会自动变为新二进制，需重新打开 UI 并重新启动建图任务。

## 实车交付验收

操作步骤与故障处理表见 [建图保存与现场处理](FASTLIO_MAPPING_OPERATOR_GUIDE.md)。
交付现场至少完成四项，并留存录包、地图目录和验收结果：

1. **单程保存**：走一段后直接保存，不回起点；拿到配套 PCD/PGM/YAML，状态明确显示未回环，旧图仍在。
2. **回环保存**：重复经过结构明显的旧路段，保存后状态显示回环检查通过；查看建筑和地面是否对齐。
3. **重新载入定位**：停止建图，载入刚保存的同一套地图，重新点选实际位姿，确认定位和点云贴合。
4. **短距离导航**：确认定位后测试实际行驶、停车与避障；不要直接套用旧图坐标中的巡检路线。

目前完成软件与同数据内部验证，尚未完成上述实车验收。不能把“文件保存成功”
或“回环检查通过”写成所有场景下可导航的保证。硬件、标定、时间同步等重复异常
按设备维护处理；现场无需修改算法或找 AI 手工修图。
