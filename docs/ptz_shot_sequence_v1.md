# 低倍视角巡检：第一版测试说明

当前版本支持一个已保存点位配置最多两个视角，倍率限定 1～4×。记录时读取实际云台角度、实际倍率与新鲜的 `map→base_link` 位姿；执行时按车头朝向变化补偿水平角。第一版只拍照存图，不调用在线识别；没有配置视角的点位继续使用原预置位巡检。

## 1. 准备

本次更新已构建安装。重启桌面界面和原来的巡检执行器 `patrol_node`；通过桌面启动导航/巡检会话时，重启该会话。独立运行的 `inspection_recorder` 使用同一数据库，也应随本次更新重启。使用网页时一并重启网页后端，它现在支持 v2～v7。

新巡检节点第一次打开数据库时，会先备份 v6 数据库，再进行保留旧数据的 v7 迁移；不要另开旧版节点操作同一数据库。

1. 按原流程启动地图定位和巡检，在桌面启动/连接相机，确认画面和“读取当前云台”可用。
2. 准备一个已保存点位，停车位置尽量在该点 10 cm 内。第一轮选择平整地面、已确认可转动范围内的低倍视角。只需要一个目标时记录一个即可，第二个视角按需添加。
3. 保持云台执勤节点运行，用于拍摄期间停转占用和手动云台互锁。若尚未运行，在一个终端执行下面的命令并保持它运行。此命令默认不旋转、不摆动；已有节点时会复用，不启动第二个。

```bash
cd /home/jkbot/Remote_ctrol
source /opt/ros/humble/setup.bash
source ros2_ws/install/setup.bash
ros2 run chassis_nav2 ptz_patrol.py
```

如果执勤巡航正在运行，先从设备执勤页停止，等待停止确认后再用手动云台标定。拍摄任务可以暂停原本开启的执勤巡航，任务正常结束后按原联动规则恢复；标定时需要手动调整视角，所以先停止巡航。

设备的水平角方向由部署配置统一管理，只需实机确认一次，所有地图、点位和视角自动共用。配置项是 `robot_patrol/config/patrol.yaml` 的 `inspection_shot_pan_sign`：镜头实际向车体左侧转动时，水平角读数减小填 `-1`，增大填 `1`。确认后写入配置并重新构建安装、重启巡检会话，即可持久使用。当前值保留为 `0`，表示等待实机确认；尚未配置时界面会说明原因，并禁止记录新视角。界面不提供逐点填写该方向的字段。

## 2. 在桌面记录视角

入口：**路线巡航 → 点位管理 → 选中已保存点位 → 到点巡检动作 → 拍摄视角（1～4×）**。

1. 将车辆停在所选点位附近，在相机页手动调好水平角、俯仰和倍率，松开控制按钮，等待车辆和画面稳定。
2. 填写视角名称，点击“记录当前拍摄视角”。后台自动读取两次实际角度和倍率，并读取新鲜定位；车辆或云台仍在运动、没有有效定位、距离点位超过 0.3 m、倍率超出 1～4× 时会拒绝保存并显示原因。此操作不移动云台或车辆。
3. 保存成功后会显示该视角的水平角、俯仰、倍率和标定车头朝向，并自动启用该点巡检、刷新点位和引用路线的版本。只需要一个视角时到这里就完成配置，以后执行巡检无需重新记录。
4. 需要第二个视角时，在下拉框选择“＋ 添加拍摄视角”，调好相机后再记录。已有两个视角时不会出现添加项。

选中已有视角后，可以调整构图并点击“重新记录所选视角”；它覆盖所选视角并保留拍摄顺序。名称、角度、倍率和对焦等待一起保存；默认到位后额外对焦等待 1.5 秒。支持“删除所选”“清空视角”和“刷新”。地图版本改变后，界面会提示清空旧视角再重新记录。记录失败时保留原配置。

录入期间禁止重复提交或从本页启动巡检，后台也拒绝同时开始巡检/返航；正在执行任务时不能修改视角。记录前先保存点位信息，视角记录按钮保存的是相机视角，不会顺带保存尚未提交的点位名称或坐标。原预置位、提示词入口保留在“原预置位与在线识别设置”中。

### 可选：命令行记录

另开终端，同样进入项目并加载 ROS 环境。先找出点位 ID：

```bash
cd /home/jkbot/Remote_ctrol
source /opt/ros/humble/setup.bash
source ros2_ws/install/setup.bash
ros2 run robot_patrol patrol_cli list-points
```

以下 `<点位ID>` 替换成上一步输出的真实 ID，不要把尖括号原样输入。

先用相机页上下左右/绝对角度输入，把镜头对准第一个目标，倍率选 1～4×，建议先用 2×。松开按钮，等画面稳定，再记录：

```bash
ros2 run robot_patrol ptz_shots record <点位ID> --shot-id wide --name 全景
```

需要第二个视角时，在同一停车位置手动对准第二个目标，再记录：

```bash
ros2 run robot_patrol ptz_shots record <点位ID> --shot-id side --name 侧面
ros2 run robot_patrol ptz_shots show <点位ID>
```

命令行与界面使用同一个后台记录接口，自动采用设备统一方向配置，无需填写 `--pan-sign`。兼容旧命令的 `--pan-sign` 参数仅校验是否与设备配置一致，不会覆盖设备配置。实机方向依据镜头实际运动和读数判断，不依据手动按钮是否配置了反向；确认时无需让车辆原地旋转。

记录命令只读角度、倍率和定位，再通过巡检服务保存，不移动云台或底盘。它会检查两次读数及车体位姿是否稳定，拒绝无效 TF、正在运动、超出倍率范围或离所选点位过远的记录。同一 `--shot-id` 再次记录会覆盖该视角并保留执行顺序。可用 `--settle-seconds 2.0` 增加到位后的对焦等待，默认 1.5 秒。

成功保存视角会启用该点的巡检动作，并增加点位及引用路线的版本。各视角的标定数据保存在巡检数据库，设备方向统一保存在部署 YAML。地图版本或设备方向改变后需要清除旧视角并重新标定；配置方向与旧视角不一致时，执行前会拒绝定位。

## 3. 发起测试

1. 桌面记录成功后会自动刷新点位和路线；使用命令行记录时回到桌面手动刷新。
2. 选中刚才的已保存点位，按原入口执行该点巡检；也可以把它放进一条测试路线执行。要选已保存点位，临时地图目标没有该点的标定序列。
3. 到点停车后，程序占用并暂停云台执勤；根据当前 TF 朝向计算目标，先定位水平，再设置俯仰和倍率。
4. 实际角度和倍率都到目标、连续稳定 0.6 秒，并完成对焦等待后，才拍第一张；如有第二个视角，再执行第二张。状态显示当前视角名称和目标。
5. 检查照片后，再驶近同一点、改变停车朝向进行第二轮测试。先比较相同目标是否仍在画面中，再测试约 10 cm 的位置偏差。

补偿公式使用标定原始值：

```text
pan_cmd = wrap360(pan_cal − pan_sign × degrees(yaw_now − yaw_cal))
```

有视角配置时优先执行视角拍摄序列，旧预置位输入不参与该序列。界面的“启用到点巡检”仍是总开关；取消勾选并保存会暂时禁用拍摄，但保留视角配置。桌面和命令行均可配置、重新记录和删除视角。

## 4. 照片与诊断记录

默认位置：

```text
~/.local/share/robot_patrol/inspections/
  run_<任务ID>/loop01/step001_<点位ID>/
    01_wide_<尝试ID>_try1.jpg
    01_wide_<结果ID>.json
    02_side_<尝试ID>_try1.jpg
    02_side_<结果ID>.json
```

实际根目录由 `inspection_image_dir` 决定。圈次、点序、视角 ID 和每次尝试 ID 都进入路径，多圈、暂停重试或再次执行不会覆盖原图。每张图对应一条数据库结果和一个 JSON，包含：

- 标定时的 pan/yaw、位置、倍率、地图版本和符号。
- 本次车体位姿、补偿后的目标及最后一次有效实际读回值。
- 图片路径、成功/失败、错误原因；异常清理时包含停止请求确认结果。

桌面巡检结果和网页报告可查看逐张结果；JSON 用于核对角度和排查偏差。序列只存图，成功结果显示“拍摄完成（仅存图）”。

## 5. 停止、失败与清除

使用原巡检任务的暂停/取消按钮。异常或取消会发送云台及镜头停止，剩余视角不再继续；迟到的定位回复之后还会补发停止。没有停止确认或旧定位请求尚未结束时，禁止开始新一轮定位。

默认约束：水平/俯仰误差各不超过 0.3°、倍率误差不超过 0.15×，一个视角的两阶段到位总预算为 30 秒；执行位置距该视角标定位置超过 0.25 m，或拍摄期间车体变化超过 5 cm / 1°，本次失败。TF 无效时不改用车体角度；未到位时不把现场图标作正常巡检照片。明确的抓拍失败最多尝试三次，超时则中止。首个失败会终止当前任务，已完成照片保留。

这些设置位于 `robot_patrol/config/patrol.yaml` 的 `inspection_shot_*` 参数中，更改后重启巡检执行器。

移除一个视角或清空：

```bash
ros2 run robot_patrol ptz_shots remove <点位ID> --shot-id side
ros2 run robot_patrol ptz_shots clear <点位ID>
```

清空后，有有效旧预置位的点恢复原预置位配置；否则关闭该点的巡检动作。此版只补偿 yaw，不补偿车体倾斜或停车平移，不承诺高倍仪表的固定 ROI 或 ±100 像素居中。

## 6. 验证范围

使用独立 ROS 域 232 的模拟相机、TF、定位和 Nav2，验证了命令行和桌面配置服务的标定读取、单视角记录、双视角重录顺序、删除清空、录入与任务互锁、保存点位单点任务、跨 0° 朝向补偿、两张独立照片、归档、不读取无效定位、角度/倍率到位、取消/暂停和迟到定位后的停止。桌面使用独立 ROS 域 216 的模拟服务验证按钮记录、重录、删除、任务运行禁用和读取失败恢复。数据库迁移、旧流程与网页 v7 兼容也有回归测试。

本轮未连接实车串口、相机或底盘，实机拍摄效果由此次现场测试确认。
