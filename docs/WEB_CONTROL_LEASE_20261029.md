# 网页切页丢失控制权与巡航联锁恢复

现场网关日志记录：浏览器 WebSocket 保持连接，但多次发生“网页控制心跳超时”；运行路线期间的一次超时使 guard 锁存 `OPERATOR_LOST`。重新取权只会建立新的控制会话，不会清除该联锁，因此下一次任务被执行器以 `LEASE_LOST / patrol guard 未就绪或心跳过期` 拒绝。

原控制心跳由控制台主线程每 300ms 发送，网关的租期为 1 秒。隔离浏览器测试在任务页切回监控台时模拟 1.6 秒渲染卡顿，复现控制权丢失和任务取消。该测试说明主线程卡顿足以触发现场故障链；现场具体是哪次渲染、浏览器调度或网络延迟造成了心跳间隙，现有日志不能独立确定。

## 修改

- 唯一控制 WebSocket 与 250ms 心跳移到 Dedicated Worker。控制台与子页面仍共用这一条连接，站内切页不释放会话，不增加第二个控制连接。
- 主页面每 250ms 向 Worker 报活；连续超过 5 秒无响应时 Worker 主动释放控制并关闭连接，避免页面挂死后无限保持任务。关闭整个控制台、真正断网和本地接管仍取消网页任务。重新连接不自动取权、恢复旧任务或重放运动命令。
- 网关的 1 秒控制租期、手动速度超时、guard 的操作端失联与锁存规则保持原值。
- 控制状态增加单调递增的所有权版本，取权响应带版本。Worker 丢弃取权之前迟到的控制快照，避免旧 `owner_present=false` 撤销新会话；不会在遥测中公开控制 token。
- 网关上报巡航联锁的真实状态、故障原因、新鲜度及复位服务可用性。网页在联锁未就绪时阻止开始新的巡航/到点/返航，并显示原因。
- 顶栏增加明确的“复位巡航联锁”。网关要求当前有效控制者、急停已解除、任务及 Nav2 目标已结束，再调用原 `/patrol/reset_interlock`。原 guard 继续核对旧目标确已终止、执行器空闲、mux/里程计新鲜和车辆停稳；拒绝原因原样显示。该操作不会启动或恢复任务。

## 使用

更新后重新启动网页服务，浏览器 **Ctrl+F5** 加载新 Worker；Qt 无需为这次改动重编译。导航仍须启用巡航联锁。

如已因旧版丢心跳锁存：确认旧任务结束、导航正常且车辆停稳，解除急停后取得网页控制权，点击顶栏“复位巡航联锁”，等待真实反馈就绪，再由操作者重新开始任务。没有联锁服务、心跳过期、旧目标未终止或车辆未停稳时不强制清除故障。

验证包含渲染卡顿后切页、页面长时间挂死释放、迟到的取权前快照、明确复位后重新执行、整页关闭/真实断网/重连、原有网页功能、网关权限与复位拒绝，以及真实 ROS guard 的失联锁存/旧目标取消/拒绝停车确认失败。浏览器与 ROS 任务测试使用本机假服务和独立 ROS 域，不向实车发送导航或运动目标。
