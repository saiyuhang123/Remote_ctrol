# JD03 建图保存与现场处理

适用版本：2026-10-26 保存流程升级。重新打开桌面 UI，并重新启动建图流程后生效。
当前用于导航的 PCD/二维切片不会因一次新建图保存而被覆盖。

## 日常操作

1. 选择「FAST-LIO 三维建图」，启动后静止几秒，等待点云稳定再走。
2. 按需要采集道路；单程、短路线都允许保存。希望消除累计漂移时，重复经过一段有固定建筑、墙角或立柱的旧路段。同向重走约 20～30 米可以增加重叠，距离本身不保证回环通过。
3. 停车，点击「保存地图」，等待 PCD 和二维切片完成。保存过程中不要停止流程或退出 UI。
4. 看“保存地图”按钮下方的结果提示。点击「打开保存目录」可直接找到本次 PCD、PGM、YAML、检查报告和使用说明。
5. 要试用新地图时，先停止建图流程，再点「载入本次地图」。UI 自动选择配套 PCD 和 YAML，并切换到 FAST-LIO 定位导航显示方案。
6. 启动定位导航，在新图上设置车辆实际位置和朝向，确认实时点云贴合，再做短距离导航测试。旧图坐标下的巡检点和路线需重新核对。

“载入本次地图”只选择文件，不会自动启动流程、解除急停或发送行驶目标。
UI 重启或重新加载默认显示方案后，仍可通过地图文件选择器打开保存目录中的 `map.pcd`；
配套导航栅格选择同目录 `map.yaml`。现有默认导航图继续保留。

## 看到不同结果怎么办

| UI 结果 | 已保存什么 | 现场处理 |
| --- | --- | --- |
| 回环检查通过 | 修正后的 PCD、二维切片和报告 | 停止建图，载入本次地图，核对定位 |
| 单程图已保存，未做回环验证 | 前端单程 PCD、二维切片和报告 | 可以查看、载入核对；需要回环修正时，继续重走结构明显的旧路段，再次保存 |
| 地图已归档，回环修正未采用 | 前端地图、二维切片、被拒绝的优化报告；没有采用变形后的地图 | 继续重走旧路段并再次保存；不使用失败优化结果进行导航 |
| 数据已归档，请检查传感器和时间戳 | 已采到的有效关键帧、可构建的 PCD、报告 | 根据日志核对雷达/IMU连接、姿态、时间戳，处理后新开建图会话 |
| 二维切片导出未完成 | 本次 PCD、检查报告和原始会话 | 展开日志查看高度过滤、超时或权限原因；保持建图流程，处理后再点保存重试 |
| 尚无足够关键帧 / 服务未就绪 | 已采到的数据保留在会话目录 | 确认处于建图模式且流程已启动；升级后重启建图；等初始化后平稳行驶一小段再保存 |
| 磁盘、目录或权限错误 | 已写入的原始会话尽量保留，不能保证本次导出完成 | 处理磁盘空间和写入权限后重试 |

回环候选默认要求两次观测间隔至少 60 秒、索引间隔至少 30 帧，以排除附近连续帧；
这不是保存条件。**不要求走满五分钟，不要求回到起点，单程也能保存地图包。**
没有回环的地图保留前端累计漂移，不能因为“保存成功”就认定定位精度通过验收。

## 文件位置与维护

默认每次会话目录：`maps/fastlio/map_session_<日期>_<PID>/`。

- 原始关键帧：`keyframes/*.npz`、`keyframes.jsonl`、`odometry.jsonl`。
- 每次保存：`exports/<时间>/map.pcd`、`map.validation.json`、`poses.npy`、`使用说明.txt`。
- UI 自动切片：同一目录下 `map.pgm`、`map.yaml`，不混用旧地图切片。
- 最近一次结果：会话目录的 `last_save.json`。

每次保存独立目录，重复保存不覆盖上一次快照，也不重复加入相同回环边。
现场出现重复异常时，将本次保存目录和对应录包交给维护人员即可，文件内有原因、
下一步操作、参数和数据来源，无需现场修改算法或找 AI 手工修图。

外参、时间同步和硬件异常不能靠保存流程自动修复；需纳入设备维护。
交付现场仍需分别完成单程保存、回环保存、重新载入定位和导航实测，
软件测试不能替代不同路面、速度与载荷下的实车验收。
