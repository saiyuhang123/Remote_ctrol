# ROS2 Qt / RViz2 桌面端

从 `/home/jkbot/Ros_Qt5_Gui_App` 移植窗口表单、停靠布局、图标与速度仪表，在独立模块内适配 ROS2 Humble。中央区域嵌入真实 RViz2，地图、激光、点云、TF、路径和代价地图沿用 ROS2 数据。

本模块独立构建与启动。原 Qt 工程及 `ros2_ws/`、`backend/`、`web/`、现有启动脚本无需修改；不运行桌面端时，继续使用原网页、命令行和独立 RViz。

## 当前已加入的 UI 功能

以下按实际界面区域记录当前功能。标注“已接入”表示桌面端已经实现对应接口，实际使用仍需要相应节点、服务或后端运行；目前已完成构建及离线模拟测试，实车联调尚未完成。

| 界面区域 / 功能 | 已加入内容 | 接入方式与使用条件 |
| --- | --- | --- |
| 主窗口与停靠面板 | 迁移旧 Qt 窗口表单、图标、速度仪表和停靠布局；通过“视图”菜单显示或隐藏面板 | 独立 Qt5 应用，不嵌入现有导航节点进程 |
| 顶部模式与显示工具 | 六种建图/导航模式选择、重新加载显示、展开 RViz 显示项与视角、点选目标和初始位姿 | 切换显示不自动切换后台算法；支持 FAST-LIO、SLAM Toolbox、Cartographer 的建图与定位导航配置 |
| 中央地图 / 雷达 / 点云 | 嵌入真实 RViz2，显示地图、扫描、点云、TF、机器人模型、路径和代价地图；保留 RViz 相机操作、选择与测距工具 | 直接读取 ROS2 数据，具体显示项取决于所选配置与实际发布的话题 |
| 连接管理 | 设置网关和业务后端地址、重新连接、显示网关连接状态 | WebSocket 连接现有网关，HTTP 连接现有业务后端；重新连接回到观察模式 |
| 操作状态与急停 | 默认观察模式、“启用操作”、急停、解除急停、取消导航 | 车辆命令统一经过现有网关；急停可在观察模式下主动点击，解除急停需要有效反馈与导航停止 |
| 目标位姿与单点导航 | 输入 X/Y/朝向、发送导航目标、设置初始位姿；支持 RViz 点选同类操作 | 使用 `map` 坐标系；界面朝向为度，发送时转为弧度；导航要求网关、定位及 Nav2 就绪 |
| 手动行驶 | 手动接管、速度/角速度设置、前进、倒车、前进左右转及倒车左右打轮；按住运动、松开停止，窗口失去激活状态时停止本次输入 | 接管时先保持急停并取消导航，再等待反馈；运动请求限幅，反馈失效或停止更新后终止持续下发 |
| 运行状态 / 速度仪表 | 实际线速度、实际角速度、当前坐标系下的位置和朝向、急停状态、网关导航状态、电量百分比和电压 | 读取真实反馈；未接入或过期时明确显示缺失状态；速度仪表单位为 cm/s，数值状态中的线速度为 m/s |
| 相机监控 | 海康实时图像、画面过期提示、云台水平/俯仰角及变倍设置 | 图像订阅 `/hk_camera/image_raw`，云台调用 `/hk_camera/set_ptz_pose`；需要相机节点运行 |
| 抓拍 / 数字仪表识别 | 相机抓拍预览、业务抓拍、按需识别当前画面、显示识别文本与置信度 | 分别使用海康抓拍服务、现有网关抓拍链路和 `/ocr/recognize`；专用仪表读数规则仍需识别模块适配 |
| 任务点位 | 刷新已有点位、显示坐标和朝向、保存当前位置为点位、删除所选点位、选点填入目标框 | 复用 `/api/points`；选点后不会自动发车，保存当前位置要求有效的 `map` 位姿 |
| 路线 / 巡检计划入口 | “打开路线 / 巡检计划管理”按钮 | 打开原有业务网页，未在 Qt 内另建一套路线/计划编辑器或自动执行器 |
| 本机会话管理 | 显式启动所选建图/导航流程、设置地图路径、选择是否启动雷达/IMU、底盘驱动和控制桥、选择里程计源、停止自身启动的会话 | 默认只连接已有系统；检测重复管线，只管理本应用启动的进程组；底盘与控制桥默认关闭 |
| 地图保存 | FAST-LIO PCD 保存、SLAM Toolbox 序列化与栅格保存、Cartographer 状态快照与栅格保存 | 调用已有服务和存图工具，检查返回结果与文件产物；FAST-LIO 的二维栅格转换继续使用现有 `pcd2pgm` 流程 |
| 消息与会话日志 | 窗口内显示带时间的操作消息、服务结果、连接异常、存图结果和子进程输出 | 便于逐项检查接口，不把发送请求当成操作完成 |
| 离线验证与截图 | 离线观察模式、六模式自动检查、定时退出、保存整个界面截图、截图成功/失败提示与退出码 | 通过启动参数使用；`xvfb-run` 下在虚拟显示器运行，不弹出桌面窗口 |

相机、OCR、点位和地图保存已与运动网关分开接入：这些功能不要求网关在线，但仍需“启用操作”及各自的 ROS2 服务或 HTTP 后端。界面不自动启动海康采集、OCR 算法或业务后端。

## 构建和启动

在项目目录执行：

```bash
./desktop_ui/scripts/build.sh
./desktop_ui/scripts/run.sh
```

构建结果为 `desktop_ui/build/robot_desktop`。脚本自动加载 Humble 与现有工作空间 overlay，默认使用 2 个编译任务，可设置 `DESKTOP_BUILD_JOBS`。输出目录可通过 `DESKTOP_BUILD_DIR` 指定，不复用原 ROS2 工作空间的构建目录。

桌面依赖安装脚本为 `scripts/install_dependencies.sh`，需要的主要开发包为 `qtbase5-private-dev`、`libqt5svg5-dev`、`libqt5websockets5-dev`。ROS2 / RViz2 沿用现有环境。相机、OCR 和电池集成在构建时自动检测本项目的 `hk_camera`、`ocr_interfaces`、`yunle_msgs` 消息包；缺失时相应功能显示不可用，不要求修改原构建流程。

当前终端没有图形桌面时可离线预览：

```bash
LIBGL_ALWAYS_SOFTWARE=1 xvfb-run -a -s '-screen 0 1600x1100x24 +extension GLX +render -noreset' \
  ./desktop_ui/scripts/run.sh --smoke-test --screenshot /tmp/robot_desktop.png
```

`--smoke-test` 使用隔离 ROS 域 218，禁用控制、业务写入和进程启动，依次加载六种模式后自动退出；`--offline` 保持离线界面不自动退出。正常启动不带这两个参数。

`xvfb-run` 使用虚拟显示器，不会在桌面弹出窗口。截图目录必须存在且可写；成功后终端打印保存路径，失败时打印错误并返回退出码 2。项目内的日志目录应写成 `./hk_log/` 或其绝对路径，`/hk_log/` 则是根目录下另一个目录。

## 连接已有系统

推荐先按原方式启动底盘、传感器、定位/导航以及需要的网关、业务后端，然后启动 Qt。启用嵌入 RViz 时，将原导航入口的 `rviz` 参数设为 `false`，减少重复显示负载。

默认配置在 [config/desktop.json](config/desktop.json)：

- 网关：`ws://127.0.0.1:8765`。
- 业务后端：`http://127.0.0.1:8888`。
- 速度反馈：`/odom`；海康视频：`/hk_camera/image_raw`。
- 电池：`/battery_status`，消息为 `yunle_msgs/msg/Battery`，容量为百分比。
- 手动速度上限：0.3 m/s，角速度上限：0.5 rad/s，仍受现有网关和底盘控制链约束。

配置可复制到自己的目录，通过 `--config /绝对路径/desktop.json` 使用；项目路径可通过 `ROBOT_PROJECT_ROOT` 或 `--project-root` 指定。窗口中的连接地址修改只影响本次会话，不覆盖现有项目配置。

界面默认观察模式，不发送速度、导航目标或急停解除指令。确认连接后勾选“启用操作”，才允许操作接口。网关断开或重连会回到观察模式。相机、OCR、点位与地图保存不依赖网关在线，但仍需启用操作及对应 ROS2 服务或业务后端。

桌面端与机器人同机运行是当前主要支持方式。异机显示还需要配置可用的 ROS2 DDS 网络、相同消息包和 TF；仅连接 WebSocket 不能获得 RViz 数据。地图文件保存及路径检查目前按同机语义工作。

## 显示模式和导航

界面提供六种显示/启动配置：FAST-LIO 建图、FAST-LIO 定位导航、SLAM Toolbox 建图与定位导航、Cartographer 建图与定位导航。

**切换下拉模式只加载显示配置，不切换正在运行的后台算法。** 建图和定位导航入口不同，各后端运行时三选一；二维建图默认不启动 Nav2。

- FAST-LIO 建图使用 `lio_odom`。
- 定位导航及二维建图使用 `map`。
- RViz 的目标/初始位姿工具发布到 `/desktop_ui/goal_request` 和 `/desktop_ui/initial_pose_request`，由桌面适配层转网关，避免绕过网关直接创建 Nav2 目标。
- 也可在左侧输入 X/Y/朝向，朝向显示为度，发送给网关时转换为弧度。
- 初始位姿下发不代表定位成功；车辆位姿以有效、未过期的 TF 为准。
- 路径、点云等显示项取决于实际发布的话题；未发布的话题可以在 RViz Displays 面板关闭。
- 默认突出地图画面，点击“显示项 / 视角”展开 RViz 原生属性与视角面板。

桌面端只使用自己的 `.rviz` 配置副本，不覆盖原配置。嵌入接口基于 [RViz2 Humble VisualizationFrame](https://github.com/ros2/rviz/blob/humble/rviz_common/include/rviz_common/visualization_frame.hpp)。

## 遥控与急停

遥控沿用现有链路：

```text
Qt → robot_gateway → /cmd_vel_teleop → twist_mux → 原底盘控制链
```

手动操作顺序：

1. 勾选“启用操作”。
2. 点击“手动接管”：网关保持急停并取消导航，界面等待真实急停反馈和导航停止。
3. 点击“解除急停（保持静止）”。
4. 按住前进、倒车或转弯按钮，松开停止；窗口失去激活状态也停止本次手动输入。

不提供原地旋转指令。倒车转弯按钮标注“左打轮/右打轮”，按反向行驶时相应的角速度符号下发。界面显示的 `ω` 是 rad/s 角速度，不冒充实际转角。

断线不缓存或重放运动请求。正常松键发送停止输入；异常通信中断依赖现有网关看门狗，当前原配置超时为 1 秒。无需手动行驶时不持续发布零速度，以免压住 Nav2 或解除急停。

急停按钮可在观察模式下明确点击使用。网页与 Qt 共用网关，当前网关没有跨客户端控制权租约，实车一次只使用一个操作前端。已有自动导航不会因为界面进入观察模式或关闭而自动取消；需要停止导航时使用取消或急停。

## 本地启动会话与地图保存

默认不启动任何机器人进程。需要由界面启动时，勾选“由界面启动与管理所选流程”，设置不带扩展名的地图绝对路径，并按实际需要选择雷达/IMU、底盘驱动和控制桥。底盘与控制桥默认关闭；FAST-LIO 建图固定使用 LIO 里程计，导航可选择原入口支持的里程计源。

启动前检测已有机器人管线；存在时拒绝重复启动，使用连接模式，或从原启动入口结束旧会话。界面仅管理自身启动的进程组，停止不会读取旧 ROS1 的 PID 文件或全局杀进程。关闭前需先结束本界面启动的会话；地图保存期间不能停止会话。

保存功能按后端分别处理：

| 建图后端 | 保存流程 |
| --- | --- |
| FAST-LIO | 调用 `/map_save` 保存建图节点配置的 PCD；检查所选路径，二维导航栅格继续使用项目现有 `pcd2pgm` 流程 |
| SLAM Toolbox | `/slam_toolbox/serialize_map` 保存 `.posegraph/.data`，然后 `map_saver_cli` 保存 `/map` 的 YAML/PGM |
| Cartographer | `/write_state` 保存包含未完成子图的 `.pbstream` 快照，然后保存 `/map` 的 YAML/PGM；不自动结束轨迹 |

保存按钮不会结束建图进程。FAST-LIO 服务不接受新文件路径：连接已有建图时，路径必须与那个节点的实际输出配置一致。保存失败时查看界面日志和原节点日志，不能把“已发送请求”当成保存完成。

## 视频、云台、OCR 与点位

- 视频订阅已运行的海康 ROS2 相机，不自动登录设备或重复启动采集。
- 云台/变倍调用 `/hk_camera/set_ptz_pose`，抓拍预览调用 `/hk_camera/capture`。
- “业务抓拍”复用现有网关及抓拍记录链路，与相机预览抓拍分开。
- 仪表识别调用 `/ocr/recognize`；当前节点使用 EasyOCR，默认按需识别。输出包括文本和置信度，具体仪表的区域、读数筛选规则继续由识别模块适配。
- 点位列表读取现有 `/api/points`，支持刷新、保存当前 map 位姿、删除所选点位；选择点位填入目标框，不自动发车。
- 路线/计划管理按钮打开原有业务页面。当前业务点位缺少地图 ID，请确认选用的是当前地图的点位。

未迁入旧任务表按距离轮询、无限循环发目标的执行代码。现有自动巡检执行器尚未接入，多点循环、无人值守调度、到点后联动云台/OCR需要后续共享执行器，不能由窗口存活状态决定。

## 验证与代码边界

`scripts/build.sh` 构建后运行测试；也可手动运行：

```bash
ctest --test-dir desktop_ui/build --output-on-failure
```

测试通过本机临时 WebSocket 服务和隔离 ROS 域验证控制协议与界面。GUI 集成测试在 Xvfb 中运行，使用伪造 TF/里程计/急停反馈，不启动底盘、导航执行器或真实相机。没有实车标定和运动精度验收。

本机已完成构建、三组自动测试和六种模式的离线切换。服务测试还覆盖模拟相机/OCR/存图响应、超时及本地进程管理。详细结果与离线预览见 [移植与验证记录](移植与验证记录.md)。

代码分为 `src/ui`、`src/rviz`、`src/adapters`、`src/runtime`。后续智能掉头、精准停靠应在独立 ROS2 导航行为或控制模块实现；这个桌面端提供操作和诊断入口，不改变原 FAST-LIO、Nav2 或底盘参数。
