# 网页巡检、报告与语音播报

本次增加网页任意点到达巡检、任务报告、识别图片上报与音频上传播放，同时修复数据库版本不兼容和巡检识别阶段取消等待。

已补齐网页点位/路线管理、固定路网预览执行、独立手动抓拍和双向语音对讲。

现已增加网页电池状态，以及云台自转与到点预置位巡检联动。

## 更新与启动

```bash
cd ~/Remote_ctrol
bash scripts/build_web_patrol.sh
source /opt/ros/humble/setup.bash
source ros2_ws/install/setup.bash
bash scripts/start_robot_monitor.sh
```

构建命令只编译，不启动底盘。更新后需要重启原有巡航执行器、云台巡航节点、网页后端、网关和视觉记录节点。导航仍按现有 Qt / chassis_nav2 流程启动，巡航需启用原有 guard/mux 联锁。

监控入口默认启动 `audio_player/tts_node`，通过机器人声卡播放音频。已有独立播放器时可设 `ENABLE_AUDIO=0`，保持同一套音频目录。视频和检测按原来的 `ENABLE_VIDEO` / `ENABLE_DETECTOR` 开启。

数据库由 `robot_patrol` 自动备份后升级到 v6，保留地图、点位、路线、运行与识别结果，新增 `inspection_reports` 表。后台兼容 v2～v6；后台本身只读巡航主库，不负责迁移。v5 已结束任务也可直接读取报告，新版巡航节点启动后会补齐历史报告快照。

## 一键到达与巡检

1. 访问 `/console.html#monitor`，取得网页控制权。
2. 在“一键到达与巡检”选择已有巡检点，或点击“地图选点与朝向”，在地图上按住并拖动设置目标和车头朝向；也可输入 X、Y、朝向。
3. 启用“到达后抓拍识别”时，选择已在相机中保存的云台预置位，按需填写识别要求。已有巡检点自动使用其保存的预置位和要求；修改字段后作为临时目标执行。
4. 点击“到达并巡检”。机器人自主规划、到点停稳、转到预置位、等待稳定、抓拍、识别并保存结果。关闭抓拍识别时只执行“一键到达”。
5. 可取消或一键返回待命点，也可切到任务页暂停、继续、取消。站内切页保留任务和控制权。

临时目标不修改点位和路线资料。坐标按地图原点朝向换算，执行器核对活跃地图、版本、范围、定位、急停和 guard；有其他任务时拒绝启动。新目标使用相同的巡航状态机、Nav2 子目标所有权及取消确认。关闭整个网页、失联或本地接管时按现有规则取消。

取消或暂停会及时结束服务等待及云台稳定等待，不再派发后续抓拍/识别。设备已经接收的服务请求不能通过 ROS 服务撤回；迟到回复被丢弃，不能改写已取消的结果。恢复暂停后重新确认到点停稳，再执行该点巡检。

## 电池状态

监控台顶部显示电量百分比、电量条、电压、电流和充电状态。数据直接来自 JD03 底盘的 `yunle_msgs/msg/Battery`，默认话题 `/battery_status`；如需修改，在 `config/config.yaml` 的 `ros.battery_topic` 设置并重启网关。Qt 沿用原有 BMS 显示。

收到有效反馈后才显示数值。电量允许真实的 0%，电量不超过 20% 时提示偏低；负电流保留底盘放电符号。反馈无效、超过 5 秒未更新，或网页连续 3 秒未收到遥测时清空旧读数，恢复反馈后自动显示。无需取得控制权，也不要求启动导航；底盘 BMS 驱动需已经运行。

## 云台自转与巡检联动

先在客户端按原有方式开启云台自转，并为巡检点保存相机预置位编号、启用到点抓拍。路线巡检和任意点巡检都使用同一流程：

1. 行驶途中保持原来自转。
2. 到点停稳后暂停自转，等相机确认停止，再转到该点的预置位。
3. 等待 `inspection_preset_settle_sec` 稳定时间，抓拍、识别、保存结果；识别和点位停留期间保持停转，避免画面被自转带走。
4. 准备派发下一点导航时释放占用，恢复原已开启的自转。
5. 最后一点正常完成后同样恢复原来自转；原本关闭自转或中途手动关闭时保持关闭。

取消、异常或巡检联动失联时保持停转，之后需要用户重新开启。占用期间 Qt / 网页显示“巡检停转中 / 巡检拍照中”，手动云台按钮锁定。内部 `/ptz_patrol/inspection_control` 租约持续续约；执行器退出后租约到期会关闭自转，禁止意外恢复。

没有启动云台自转节点时仍可独立执行预置位抓拍；发现旧版自转节点但没有停转联动接口时拒绝继续抓拍，请先更新并重启。相机不提供可靠的绝对角度回读，所以仍通过预置位和稳定等待完成定位，需要现场确认每个预置位及等待时间。

## 报告与识别记录

打开“巡检记录”：

- **巡检报告**：完成、失败、取消或中断后自动生成，保留任务快照、地图和路线版本、起止时间、完成点数、到点停车结果、抓拍识别及异常。支持分页查看、HTML / JSON 下载。
- **HTML 报告**：内嵌抓拍缩略图，可离线打开；浏览器打印时选择“保存为 PDF”。JSON 保留结构化结果和在线图片地址。
- **到点抓拍与仪表识别**：查看图片、识别文本、成功或失败原因，可按任务筛选。
- **人脸、行人和车牌**：查看上传的图片、识别内容、时间、地图与位置；支持类型、任务筛选和分页。无定位时仍保留图片，位置显示“无定位”。

视觉记录器默认上传。旧记录经持久 outbox 补传；网络或后台中断不影响本地记录，恢复后自动重试。后台按 `event_id` 去重。任务记录按事件时间和地图关联，无定位记录也可按任务时间窗口关联；迟到上报在刷新报告时补入。

## 网页点位和路线管理

1. 打开“巡检任务”，取得网页控制权，确认当前地图版本一致，并结束活动任务。
2. 在“点位与路线管理 → 巡检点”新增点位。填写名称、坐标和朝向，或点击“地图选点与朝向”，在右侧地图按住拖动。按需启用到点抓拍、填写云台预置位和识别要求，再保存。
3. 在下拉框选择已有点位修改。保存会检查读取时的版本；Qt 或其他会话修改过资料时会拒绝覆盖，重新选择后再编辑。被路线引用的点位拒绝删除，先修改对应路线。
4. 展开“巡检路线”，新增或选择已有路线，设置名称和导航方式。逐个加入点位，可重复添加，使用上移、下移、移除调整点序，并填写各点停留秒数。保存后上方任务列表同步更新。
5. 固定路线选择当前地图已发布的录制路网；各点需已绑定到该路网。网页可维护使用这些道路的业务路线；道路本身的录制和发布仍使用本地 Qt。

资料通过 WebSocket 网关调用既有 `UpsertPoint/UpsertRoute/DeletePoint/DeleteRoute` 服务保存，保持巡航主库单一写入路径。HTTP 后台不直接修改主库。失联或地图版本变化后不能继续提交旧表单。保存超时后先刷新核对，避免重复新增。

## 网页固定路线预览与执行

导航会话需启用 `enable_patrol:=true enable_recorded_routes:=true`，使用原 guard/mux 和固定路线 Nav2 插件。

1. 在任务列表选择固定路线，设置圈数或趟数，点击“预览固定路线”。
2. 右侧地图显示实际行驶段，绿色为前进、橙色为倒车；预览包含后端规划的自动接入段。
3. 确认后点击“立即执行”。网页发送刚刚取得的计划摘要，执行器再次核对路线、路网、地图和起始位姿。
4. 更换路线、修改圈数、修改资料或移动起点后需重新预览。缺失录制连接时仍拒绝执行，不改用自由导航绕过路网约束。

暂停、继续、取消、返航及失联处理沿用原有任务控制。非闭环简化录制路径的圈数沿用原定义：1 为单程、2 为往返。

## 独立手动抓拍

监控台“实时视频”下点击“立即抓拍并保存”，无需启动导航或巡检任务。成功后显示最新抓拍，可打开原图；“巡检记录”底部有独立手动抓拍图库和分页。

需要 `capture_server` 和新鲜视频源，例如 `ENABLE_VIDEO=1` 时监控脚本默认启用抓拍；已有外部视频源时使用 `ENABLE_CAPTURE=1 VIDEO_SOURCE=实际视频源`。无新鲜帧、写盘失败和响应超时会明确显示，不能把旧视频帧当作成功抓拍。

图片保存在 `web/captures/日期/`，后台在独立记录库中持久保存索引；上传失败由原有缓存补传。保留原来的图片轮转策略，过期清理后记录显示“图片已过期或被清理”。

## 音频上传和播放

在监控台“机器人语音播报”上传 MP3、WAV、OGG、M4A 或 FLAC，最大 20MB、最长 10 分钟。后台检查实际音轨及长度，保存后选择音频并点击“机器人播放”。声音从机器人扬声器输出，网页显示排队、播放、完成或错误。“停止播报”停止当前播放并清空待播队列。

上传不要求运动控制权；播放和停止要求当前网页控制权及新鲜的播放器状态。音频列表重启后保留。此次语音范围是上传、一键播放和停止。

## 双向语音对讲

入口位于整个控制台顶栏 **“麦克风 / 音响”**。网页选择设备并主动点击“开启对讲”，机器人声卡被动开启录音和播放，不需要本地点击接听。没有通话时不打开录音流；没有麦克风或音响时显示未就绪，接入后刷新设备。

使用系统声卡 / USB 麦克风和音响，支持选择网页端、机器人端的输入输出设备。完全不调用海康相机的音频、对讲或 SDK 通道。网页麦克风送到机器人音响，机器人麦克风送到网页音响；两路可分别静音。部分浏览器不支持选择输出设备时，使用系统默认音响。

收起对话框、切换监控/任务/记录页不会挂断。点击“结束对讲”、刷新或关闭整个页面、断网、控制权释放或本地接管会结束通话并释放设备。开始对讲会停止已上传音频的播报，对讲期间禁止新播报，避免两路声音竞争。

机器人音频依赖安装：

```bash
sudo apt install libportaudio2
python3 -m pip install --user sounddevice
python3 -m sounddevice  # 只列出声卡，便于核对设备编号与名称
```

默认使用机器人系统默认声卡，也可在网页选择设备，或在网关启动前设置 `ROBOT_INTERCOM_INPUT_DEVICE` / `ROBOT_INTERCOM_OUTPUT_DEVICE` 为设备编号或名称。当前格式为 48kHz、单声道 PCM16，声卡需支持该格式。当前机器已安装 PortAudio 和 sounddevice，已能枚举 USB Audio 输入/输出设备；尚未进行实际录音、播放、回声和时延验收。现场可使用耳麦或带硬件回声处理的麦克风/音响组合。

### 远程浏览器 HTTPS

浏览器麦克风要求安全上下文，远程访问使用浏览器信任的 HTTPS 证书；`localhost` 可用于本机测试。详见 [getUserMedia 浏览器要求](https://developer.mozilla.org/en-US/docs/Web/API/MediaDevices/getUserMedia)。准备包含实际访问主机名或 IP 的证书，并在浏览器端信任其颁发者；只忽略自签名证书错误不能保证麦克风权限可用。

```bash
export ROBOT_TLS_CERT=/绝对路径/server.crt
export ROBOT_TLS_KEY=/绝对路径/server.key
ENABLE_VIDEO=1 bash scripts/start_robot_monitor.sh
```

访问 `https://证书对应主机:8888/console.html`，控制与对讲使用同一证书的 WSS 8765。启用视频时脚本同步为 MediaMTX 8889 启用 HTTPS；其证书设置依据 [MediaMTX 配置](https://mediamtx.org/docs/references/configuration-file)。浏览器需能正常访问这三个端口。

本机上传保留 `127.0.0.1:8887` 的 HTTP 入口，监控脚本自动设置 `ROBOT_BACKEND_URL=http://127.0.0.1:8887`，不会关闭证书校验。独立于脚本启动的 Qt、视觉或抓拍进程也需设置相同上传地址。未启用 TLS 时仍使用原有 HTTP 8888 / WS 8765；远程普通 HTTP 页面会提示麦克风需要 HTTPS。

## 数据目录

| 环境变量 | 默认位置 / 作用 |
|---|---|
| `ROBOT_PATROL_DB` | `~/.local/share/robot_patrol/patrol.sqlite3`，后端与巡航节点保持一致 |
| `ROBOT_AUDIO_DIR` | 项目下 `data/audio`，后端、网关、播放器保持一致 |
| `ROBOT_WEB_RECORDS_DIR` | 项目下 `data/web_records`，后台视觉记录库和收到的图片 |
| `ROBOT_BACKEND_URL` | `http://127.0.0.1:8888`，视觉记录上传目标 |
| `ROBOT_INSPECTION_IMAGE_DIR` | 后台允许读取的到点抓拍目录，默认 `~/.local/share/robot_patrol/inspections`；自定义巡航 `inspection_image_dir` 时同步设置 |

播放需要 FFmpeg / ffplay、可用声卡和正确的扬声器输出。到点巡检需要海康抓拍/预置位服务，以及已配置的图片识别服务。隔离测试使用假设备，实际相机、扬声器和车辆效果需要现场验收。
